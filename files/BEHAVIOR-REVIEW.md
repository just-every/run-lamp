# Behavior statements checked

Run Edit Run fleet, 17 November 2026 UTC.

- Automatic maintenance: `src/core/features/maintenance/service.ts:runDue` reads the saved `autoStart` and `autoComplete` switches before transitions. `maintenance.repository.ts:listDue` supplies due windows. The Overview service already returns these actual switches and timestamps. The new Scheduled sentence uses them and the configured page time zone, only while the relevant step is future. Manual completion is identified when that switch is off.
- Missed work: the follow-up SQL projects a still-Scheduled automatic start only after its saved start, and a still-In-progress automatic completion only after its saved end. Existing failures, dismissals and current-occurrence matching remain intact. The public-door follow-up journey creates both missed cases and runs the real scheduled entry to recover them.
- Subscriber reminders: `runDue` sends due reminders through the existing reminder policy; MAINT-005 calls for the automatic twenty-four-hour reminder. A future reminder therefore needs no owner action. It appears only after due and while unrecorded. Existing overdue reminder proof remains in the follow-up journey.
- Local email: `src/core/app/mail.ts:createAppMailTransport` substitutes `developmentMail()` for local execution. The composed sender, not an environment provider name, determines `/api/app/mail-settings`. The existing local subscriber journey checks actual suppressed delivery records. Disabled or unconfigured hosted mail also reports no available primary provider.
- Texts: `src/core/features/sms/service.ts:configured` checks the Twilio inputs, subscriber token support, paused effects and hosting availability. Local mail suppression does not itself suppress SMS. The new combined sentence says “emails or texts” only when this separate endpoint explicitly reports texts unavailable; otherwise it says only email. This reduces the unconditional design wording to preserve truth.
- Hosted email: real provider configuration restores the From field. Existing hosted provider, preference, publication and provider-acceptance checks exercise that path. The future-email sentence says confirmed subscribers *can receive published updates*, avoiding a promise about unconfirmed subscribers, paused effects or delivery outcomes.
- Computer-only access: the quiet line is restricted to a non-preview public origin whose host is loopback. `notificationOrigin` and local page-host preparation supply that actual origin. Hosted origins do not satisfy this condition.
- Technical instructions: the pre-existing provider guide already documents each setting and redeployment step. Their UI names now live in one collapsed Details section; the inactive From address is read from settings there. No deployment service, sender address or time is invented.
- Missed start wording says to open maintenance rather than offering a new one-click Start action: existing automatic windows require changing their auto-start choice before the manual start door is available. This round does not change that maintenance flow.

Scope note: the existing SMS Support contact may still inherit the local placeholder sender address. This field and fallback predate this round; changing that preference behavior is outside the two selected fixes.
