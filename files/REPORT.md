## Plan and implementation

The full ordered plan is in PLAN.md. The implementation follows that plan:
generate the incumbent's documented REST/public envelopes and independent field
inventory; walk original JSON leaves before normalization; bind each disposition
to the immutable reviewed plan; expose the same searchable and downloadable
ledger on dry runs, saved jobs and verification; prove the census, refusal and
silent lifecycle through ordinary HTTP doors; regenerate/check the contract,
restore generated views, and regenerate/check the source lock last; publish only
the named product branch and return reports separately through the evidence ref.

The new generator has no clock, randomness, account, credential or provider API
dependency. Its sources file names the public documentation and distinguishes
invented forward-compatibility, consent and hostile-input probes from documented
fields. The independent inventory enumerates scalar/null leaves and empty
objects/arrays directly from the source JSON. It does not import the Lamp mapper.

Every accepted source leaf has a file, RFC 6901 path, disposition, reason and next
action. Dispositions are mapped, changed, raw-only, deleted and refused. Fields
are stored with their source record; safe page/envelope data is retained in
metadata. Shared explanation dictionaries keep repeated subscriber descriptions
out of every retained plan chunk. Reports expand these data without reclassifying
the source at read time. Erased entries do not contribute ledger rows.

Unknown nested fields, page/support/settings data, subscriber profile fields,
notice tags/synopses, metrics summaries and parent-only component descriptions
remain explicitly raw-only. Long component/group names, descriptions and notice
titles name shortening. Full incident text remains in imported history, with the
bounded native summary disclosed. Source channel/capability values are excluded
from sanitized records and original custody is withheld where required. A nested
capability refuses the input with a named path and next action, without echoing
its value. Unsupported files refuse with a named filename and whole-file scope.

A parent still becomes exactly one visual group, including the existing nested
flattening explanation. The UI adds native disclosure/search/filter/pagination
and a complete value-free JSON download within Settings → Move in. Existing
styles and navigation are retained. No other importer semantics are changed.
