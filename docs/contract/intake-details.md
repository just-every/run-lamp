# Intake, automation, drafting, team and reporting details

Historical source and mechanism notes retained from commit `54e0e1dcfdc225ad17e42abff04b65d7f2bfdc72`. Statements of proof below describe that source revision; current acceptance and status are in CONTRACT.md.

## INTAKE-001 source record

Each source is configured with one of two credentials. With a signing secret, a request is accepted only when the HMAC-SHA256 over its timestamp header and raw body matches and the timestamp is within 5 minutes of the deployment's clock; the signature is verified over the received bytes before they are parsed. With a bearer token, a request is accepted only when it presents that token, which exists because most monitoring tools — among them Datadog, Pingdom, and Uptime Kuma — cannot sign a webhook at all. A request with an absent, malformed, stale, or non-matching credential returns 401 and creates nothing.

## INTAKE-003 source record

Alerts carrying the same deduplication key produce one incident for as long as that incident is unresolved: an alert whose key matches an unresolved incident is recorded against that incident and creates no second one. A redelivery of a request already accepted creates no additional incident, draft, or alert record and returns the same status as the first delivery.

## INTAKE-006 source record

A source can be a preset for Datadog, UptimeRobot, Better Stack or Pingdom, mapped to one component. Its endpoint accepts only that tool's documented alert payload (Datadog's webhook variables in the template Lamp shows, UptimeRobot's JSON webhook variables, Better Stack's incident webhook, Pingdom's state change webhook), authenticated by the source's token presented as a bearer header or as the endpoint's last path segment for tools that cannot send a header; the token is shown once, when Lamp generates it. A missing or wrong token returns 401 and records nothing; any other payload returns 400 and is recorded against the source. A firing alert creates or updates a draft incident attached to the mapped component, never a published one.

## INTAKE-009 source record

Until that secret is saved, every inbound event is refused; the source card reports the webhook connection separately from the optional REST connection. The preset checks the exact raw request body using HMAC-SHA256 hex and constant-time comparison against every comma-separated `v1` signature in `X-PagerDuty-Signature`, following [PagerDuty’s signature specification](https://docs.pagerduty.com/developer/verifying-webhook-signatures). The optional REST API key and note-author email are sealed with AES-GCM, never displayed and excluded from archives; a restored connection requires reconnection. Without a key no note is sent. The note-author email defaults to the source owner’s Lamp email, which must identify a valid PagerDuty user: PagerDuty requires its `From` header for [creating an incident note](https://docs.pagerduty.com/developer/api/reference/rest/incidents/create-incident-note). [Connection instructions](../alerts-from-monitoring-tools.md#pagerduty) cover the v3 subscription and optional note connection. ## INTAKE-013 source record

Every component has its own automation email address, as Statuspage's components do, so monitors that can only send mail (Pingdom email alerts, CloudWatch alarms through SNS email, New Relic email, cron scripts) change component state with no webhook. Mail is received by a Cloudflare Email Worker on an inbound subdomain the owner chooses (for example `automation.status.example.com`), whose MX records Settings shows and a setup check verifies. The address is `c-<token>@<inbound domain>`, where the token addresses one component and carries at least 128 bits of entropy. It is shown in the component's Automation panel, can be rotated (the old address is refused from then on), and is stored only as a hash. The semantics are Statuspage's. A subject containing the word `DOWN` claims Major outage, and one containing `UP` releases the claim; the words match whole and in capitals, and when a subject holds both, the first one decides. The Automation panel states this rule beside the address, and a message whose subject holds only a lower-case or mixed-case `down` or `up` is refused with the reason "keyword not in capitals", so a monitor sending `Down` is visible on the source instead of silently doing nothing. Statuspage's address suffixes, as in `c-<token>+partial_outage@` and `c-<token>+degraded_performance@`, claim those states instead, and a suffixed address never releases a claim, so recovery needs the plain address. Pingdom's alert subjects ("DOWN alert: …", "UP alert: …") parse with no extra setup. Mail is processed in the order received and deduplicated by `Message-ID`. While an unresolved incident or in-progress maintenance claims the component, a message changes nothing and is recorded as ignored, as Statuspage ignores it. The component's AUTO-001 rule decides what an accepted message does: draft, claim, or claim and publish. AUTO-002's flap guard applies as to any source. The owner can also require that the sending domain pass DMARC alignment, or limit senders to listed addresses or domains. A message to an unknown or rotated token, from a refused sender, or with neither keyword is rejected during the SMTP session and records nothing on any component; refused and unparsed messages are counted on the source with their reason, without storing message bodies. Cutover (MOVE-006) lists each imported Statuspage component's old `automation_email` beside its new Lamp address, so the owner can repoint every monitor. The release that ships this clause records MOVE-006 as changed. Acceptance: an inbound-mail fixture with subject `DOWN alert: api is DOWN` sent to component API's address claims Major outage within 30 seconds under a "claim" rule. The same message under a "draft" rule creates a private draft attached to API and changes no public state. `UP` to the plain address releases the claim, and `UP` to the `+partial_outage` address releases nothing. A message to an address with a wrong token is rejected at SMTP and records nothing. A message while an incident claims API is recorded as ignored. A message with subject `api is Down` is refused and counted with the reason "keyword not in capitals". After a Statuspage fixture import, Cutover lists each component's old and new automation address. Status: **missing**. Lamp has no inbound email path.
